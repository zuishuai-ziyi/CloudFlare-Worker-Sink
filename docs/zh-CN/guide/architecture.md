# 架构

Sink 以单一长生命周期的 Node.js 进程运行仪表盘、API 和短链接跳转。在 Cloudflare Pages/Workers 上时通过不同绑定跑同一份代码；该路径现已移到 `cloudflare/` git 子模块，仅作存档参考。

## 有人打开短链接时发生什么

1. 访问者打开你域名下的短链接
2. Sink 查找链接并跳转（或显示密码/警告页）
3. 你在仪表盘或通过 API 管理链接（都需要登录）
4. 访问会出现在报表和日志里 —— 访问分析是内建功能

## Node 运行时使用的存储

Node 运行时会自动替换所有 Cloudflare 绑定 —— 无需配置：

| Cloudflare 名称 | Node 端等价物                              | 是否必需 | 白话说明                          |
| --------------- | ------------------------------------------ | -------- | --------------------------------- |
| `DB`（D1）      | `<NUXT_DATA_DIR>` 下的 SQLite 数据库       | 必需     | 主数据库 — 链接真正存放的地方     |
| `KV`            | 同一数据库中的 `kv_store` 表               | 必需     | 加速跳转的缓存 + 一次性初始化标记 |
| `ANALYTICS`     | 同一数据库中的 `access_logs` 表            | 内建     | 访问事件，供图表和日志使用        |
| `R2`            | `<NUXT_DATA_DIR>/r2/` 下的文件             | 内建     | 备份和社交分享图片                |
| `AI`            | 任意 OpenAI 兼容端点（`NUXT_AI_BASE_URL`） | 可选     | 建议短链码和标题                  |

SQLite 数据库是链接的真正存储。`kv_store` 表是用于快速跳转的副本。保存链接后，Sink 会更新缓存；若缓存不对，会丢掉再从 SQLite 重新加载。

首次部署后，请打开一次 **Dashboard → Links**，完成存储初始化。在此之前，大多数链接 API 会提示「存储未就绪」（HTTP 423）。详见[存储初始化 / 迁移](/zh-CN/storage/kv-to-d1)。

AI 是可选的，只有同时设置 `NUXT_AI_BASE_URL` 和 `NUXT_AI_API_KEY` 才会启用。请从[快速开始](./getting-started)开始。
